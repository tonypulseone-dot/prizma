# ТЗ: сервис бесплатного SEO + GEO аудита (клон функций вебпоиск.рф/seo-audit)

> Источник анализа: https://вебпоиск.рф/seo-audit (xn--90abjnkwgs.xn--p1ai), снят 23.09.2026.
> Проведён реальный аудит (сайт самого сервиса), разобраны HTML, JS-бандлы Next.js,
> RSC-payload отчёта, API-эндпоинты и выгружаемый файл отчёта.
>
> Цель: повторить **всю функциональность** (анализ сайта, отчёт, графики, выводы, план работ,
> GEO-проверка, кабинет, тарифы) в **другом дизайне** лендинга.
> Дизайн-референсы пользователь пришлёт отдельно (см. раздел 12 «Открытые вопросы»).
>
> Важно: тексты проверок (объяснения, рекомендации) у оригинала авторские. В нашем сервисе
> пишем свои формулировки. В этом ТЗ описана логика и пороги, а не скопированный копирайт.

---

## 1. Что делает сервис: сценарий пользователя

1. Человек вводит адрес сайта в форму на лендинге («Адрес Вашего сайта» → «Проверить бесплатно»).
   Регистрация, карта и email не нужны.
2. Форма — обычный HTML `POST /api/audit` (поля `url`, `returnTo`), работает даже без JS.
   Сервер создаёт аудит и отвечает `303 See Other` → `/report/{uuid}`.
3. Страница отчёта сначала показывает **экран прогресса** (4 шага, %, «Страниц проверено: N из M»).
   Клиент опрашивает статус каждые 2 с.
4. Через 1–2 минуты страница превращается в **полный отчёт** по постоянной ссылке.
   Данные PageSpeed подгружаются асинхронно, уже после основного отчёта.
5. Отчёт можно **скачать** (самодостаточный HTML-файл) и переслать разработчику.
6. Дальше идут воронки: GEO-проверка видимости в ИИ, регистрация на тариф, кабинет с историей аудитов.

### 2.1. API-контракт (повторить 1:1)

```
POST /api/audit                 form: url, returnTo      → 303 Location: /report/{id}
GET  /api/audit/{id}/status     → {
        "status": "pending|running|done|failed",
        "psiStatus": "pending|ready|failed",
        "progressStep": "Читаем robots.txt | Обходим страницы | Проверки | Считаем балл | Готово",
        "progressPercent": 0..100,
        "pagesCrawled": 20, "pagesPlanned": 20,
        "score": 90, "errorMessage": null }
GET  /api/report/{id}/download  → text/html; Content-Disposition: attachment;
                                  filename="otchet-{host}-{YYYY-MM-DD}.html"
POST /api/visibility            form: brand, category, audience, region, site, competitors, email
                                  → отчёт GEO-видимости
GET  /report/{id}               страница отчёта (SSR, данные сразу в HTML)
GET  /register?plan=start|growth|leader|max
GET  /cabinet, /cabinet/referral
```

### 2.2. Модель данных отчёта (то, что получает страница `/report/{id}`)

```ts
type Report = {
  auditId: string;                       // uuid, он же постоянная ссылка
  initial: AuditStatus;                  // как в /status
  issues: Issue[];                       // ВСЕ проверки реестра (и пройденные, и нет)
  categories: { key: CategoryKey; label: string; score: number; passed: number; failed: number }[];
  pages: { url: string; issues: number; critical: number }[];   // сортировка по issues desc
  keywords: { words: {term: string; score: number}[];  // топ-12
              phrases: {term: string; score: number}[] }; // топ-10, 2–3-граммы
  psi: { strategy: "mobile"|"desktop"; status: "ok"|"error";
         performance: number; accessibility: number; bestPractices: number; seo: number;
         lcpMs: number|null; cls: number|null; inpMs: number|null; errorMessage: string|null }[];
};

type Issue = {
  checkId: string;            // "title-length-range"
  category: CategoryKey;      // "meta"
  categoryLabel: string;      // "Мета-теги"
  severity: "critical" | "important" | "advice";
  passed: boolean;
  title: string;              // название проверки ("Длина title в пределах 30–65 символов")
  details: string;            // факт по сайту ("Страниц с неподходящей длиной title: 8.")
  explain: string;            // почему это важно
  recommendation: string;     // что сделать (1-е предложение = заголовок пункта плана)
  impact: string;             // «Что это даст»
  affectedUrls: string[];     // страницы, где найдено
};
type CategoryKey = "technical"|"meta"|"indexing"|"ai"|"content"|"structure"|"markup"|"mobile"|"trust";
```

## 3. Конвейер аудита (воркер)

Прогресс-шаги (фронт определяет активный шаг по подстроке в `progressStep`):
`robots` («Читаем robots.txt») → `crawl` («Обходим страницы») → `checks` («Проверки», «Считаем балл», «анализ»/«ссылки») → `done` («Готово»).

1. **Нормализация URL.** Добавить `https://`, поддержать IDN (кириллические домены → punycode),
   отсечь путь до корня сайта. Проверить, что хост резолвится и не приватный (защита от SSRF).
2. **Сетевые пробы домена:** http→https редирект, www/без-www склейка, цепочки и петли редиректов,
   запрос заведомо несуществующего адреса (ожидаем 404 и «свою» страницу 404), заголовки безопасности,
   сжатие, кэш, HSTS, версия сервера.
3. **robots.txt:** доступность, парсинг, `Disallow: /` для `*`, строка `Sitemap:`,
   доступ для 10 AI-ботов (GPTBot, OAI-SearchBot, ChatGPT-User, PerplexityBot, ClaudeBot,
   anthropic-ai, Google-Extended, Bingbot, YandexBot, Applebot-Extended).
4. **sitemap.xml:** доступность, валидный XML (`urlset/loc`), тот же домен, есть главная.
5. **Обход (crawl):** BFS от главной + адреса из sitemap. Лимит **20 страниц** (`pagesPlanned`) на
   бесплатном тарифе. Только свой хост, уважать robots, таймауты, 2–4 параллельных запроса.
   Для каждой страницы сохраняем: код, TTFB, вес, заголовки, HTML, ссылки, картинки (HEAD для веса).
6. **Проверки:** прогон всего реестра (раздел 4). Каждая проверка возвращает
   `passed | failed | not_applicable`, `details` (факт с числами) и `affectedUrls`.
7. **Ключевые слова** (раздел 6).
8. **Балл** (раздел 5). После этого `status=done`, отчёт уже показывается.
9. **PageSpeed** — отдельная задача, `psiStatus=pending → ready/failed`. Фронт после `done` опрашивает
   статус ещё до 45 раз по 2 с, затем делает `router.refresh()`.
   PSI **не входит** в общий балл, это только информационный блок.

Таймауты фронта: основной поллинг идёт до 150 попыток по 2 с (~5 мин), потом пишет
«Не удалось получить статус, обновите страницу». При `failed` показывается `errorMessage`.

## 4. Реестр проверок (127 штук, 9 направлений)

Счётчик проверок на лендинге **вычисляется из реестра**, его не пишут руками.
У оригинала здесь рассинхрон: на лендинге «128», в мета-описании «112», в реестре фактически 127.
У себя делаем одну константу `REGISTRY.length`.

Важность: **К** — критично (вес 5), **В** — важно (вес 3), **С** — совет (вес 1).

```ts
  title: "Длина title в пределах 30–65 символов",
  explain: "...почему это важно (наш текст)...",
  recommendation: "Первое предложение — короткое действие. Дальше — детали/пример кода.",
  impact: "...что это даст бизнесу...",
  run: (ctx: SiteContext) => ({ status: "failed", details: "Страниц с неподходящей длиной title: 8.", affectedUrls: [...] })
}
```

Правило для `details`: всегда **факт с числом** («Полей без подписи: 57.», «Страниц без `<main>`: 19 из 20.»,
«Заголовки раскрывают версию: nginx/1.31.2.»). Для пройденных проверок тоже пишем подтверждение
(«Все 10 AI-ботов из методики допущены на сайт.», «Сервер отдаёт Last-Modified: …»).

## 5. Формула балла (проверена на реальных данных)

- Вес проверки: критичная **5**, важная **3**, совет **1**.
- **Балл категории** = `round(100 × Σвес(пройденных) / Σвес(применимых))`.
  Сверка с реальным отчётом: technical 57/58 → 98, meta 40/44 → 91, indexing 44/44 → 100, ai 19/22 → 86,
  content 29/34 → 85, structure 22/26 → 85, markup 21/24 → 88, mobile 17/22 → 77, trust 24/33 → 73.
  Совпало во всех 9 категориях.
- **Общий балл** = средневзвешенное по категориям, веса в сумме 100. Опубликовано: Техника 20, Мета-теги 20,
  Индексация 15, «и так далее». Остальные 45 пунктов по реальным данным сходятся при
  **7,5 на каждую из шести оставшихся категорий** (получается 89,9 → 90, как в отчёте).
  Берём эту схему как стартовую.
- Шкала: **0–49 «Плохо»**, **50–79 «Средне»**, **80–100 «Хорошо»**. Заголовок отчёта: «Хороший результат» / «Средний…» / «Плохой…».
- PageSpeed в общий балл **не входит**.

## 6. Ключевые слова и фразы

- Источник — тексты обойдённых страниц. **Вес зоны:** title и H1–H3 и meta description весят больше основного текста.
- Токенизация RU/EN, нижний регистр, стоп-слова (оригинал их фильтрует плохо: в топе оказалось «что», у нас стоп-лист лучше).
  Лемматизация — через pymorphy3/mystem (у оригинала её нет, это можно улучшить).
- **Слова**: топ-12 по взвешенной частоте (`score` абсолютный). **Фразы**: n-граммы из 2–3 слов, топ-10, `score`
  нормирован к 100 для первой фразы.
- Подпись в отчёте: частотность в Яндексе не измеряется, это то, «о чём сайт фактически рассказывает».
  Призыв: «если важной услуги нет в списке — о ней мало написано».
- Для платного тарифа можно добавить Wordstat/Topvisor.

## 7. Страница отчёта `/report/{id}`: блоки, графики, выводы

Слева или сверху — навигация «Разделы отчёта» с якорями и счётчиками:
Балл · План (12) · По важности · По категориям · Страницы (20) · Скорость · Ключевые слова · GEO · Все проверки (N замечаний).

1. **Шапка:** «Аудит сайта {url}», «Проверка запущена {дата, время}».
2. **Hero-итог (`#score`):**
   - Круговой **гейдж балла 0–100**, цвет по шкале 0–49 / 50–79 / 80–100 и легенда шкалы.
   - Заголовок-вердикт («Хороший результат») и подзаголовок.
   - Стат-плитки: «Страниц проверено: 20», «Пройдено проверок: 109 из 127».
   - Кнопка **«Скачать отчёт»** (`/api/report/{id}/download`).
3. **План «Что сделать» (`#action-plan`):**
   - Берём непройденные проверки, сортируем critical → important → advice (внутри — по весу категории
     или по числу затронутых страниц) и показываем первые **12**.
   - Пункт: номер, бейдж важности, категория, **заголовок = первое предложение `recommendation`**
     (обрезка до первой «. »), строка «Затронуто страниц: N» (или `details`, если URL нет),
     строка «**Что это даст:** {impact}».
   - Внизу: «Мы показали главное — ещё N замечаний ждут в полном списке» → якорь `#all-checks`.
   - Если провалов нет: «Критичных проблем не найдено» и список советов, чем заняться дальше.
4. **«Найденные проблемы по важности» (`#severity`):** всего замечаний, **горизонтальная
   stacked-полоса** (Критично / Важно / Совет) и легенда со счётчиками.
5. **«Профиль по категориям» (`#categories`):** 9 горизонтальных баров 0–100, сортировка по возрастанию
   (слабые сверху), отметки порогов 50 и 80 на полосе, подпись «Пройдено X из Y».
6. **«Что нашли на каждой странице» (`#pages`):** таблица «Адрес | Замечаний | Критичных»,
   сортировка по убыванию, длинные URL обрезаются посередине (`/p…rmy/wordpress/`).
   Сноска: сайтовые находки (robots, sitemap) в таблицу не попадают.
7. **«Скорость сайта по данным Google» (`#speed`):** переключатель **Мобильные / Компьютер**,
   **4 кольца** Lighthouse (Производительность, Доступность, Лучшие практики, SEO), всего 4×2.
   Ниже Core Web Vitals с нормами и оценкой:
   LCP (≤2,5 с хорошо), CLS (≤0,1), INP (≤200 мс). Если данных нет — «нет данных».
   Сноска, что блок не входит в балл. Пока `psiStatus=pending` — скелетон и поллинг.
8. **«Ключевые слова и фразы» (`#keywords`):** два облака или списка чипов + пояснение.
9. **GEO-тизер (`#geo`):** «Видимость в AI-ассистентах — отдельная проверка», объяснение методики
   и CTA «Проверить видимость в ИИ» → `/geo` (предзаполнить сайт).
10. **«Все проверки» (`#all-checks`):** табы-фильтры по категориям; группы «Важно (8)» / «Совет (10)» /
    «Критично» с подписями («Заметно влияет на позиции…», «Не срочно, но сделает сайт аккуратнее»).
    Каждая строка: название, `details`, раскрывашка **«Подробнее»** (explain + recommendation +
    impact + список URL). Ниже свёрнутый список «**Пройдено N проверок**» с галочками.
11. **«Как считается балл»** — прозрачная методика (веса 5/3/1, веса категорий, неприменимые не считаются).
12. **Постоянная ссылка** на отчёт и приписка «Сохраните ссылку — отчёт доступен без регистрации».
13. Футер с CTA «Проверим Ваш сайт?» и бегущей строкой преимуществ.

### 7.1. Экран прогресса (пока `status != done`)
Карточка «Проверяем сайт. Обычно занимает 1–2 минуты, страницу можно не закрывать»:
степпер из 4 шагов с галочками («✓ Читаем robots.txt — пройдено»), прогресс-бар %,
«Страниц проверено: X из Y» и сразу же постоянная ссылка на отчёт.

### 7.2. Скачиваемый отчёт (самодостаточный HTML, инлайн-CSS, печатается в PDF)
Разделы: шапка (сайт, дата, ссылка на онлайн-версию) → балл + вердикт + 4 цифры
(страниц, пройдено проверок, критичных, важных) → «По направлениям» (таблица) → «Скорость по Google
PageSpeed» (таблица) → «Ключевые слова и фразы» → **«Вывод»** → **«Пошаговый план»** →
«Что сделать — подробно (N)» (каждая находка с details, recommendation, URL) → «Проверенные страницы (N)».

**Генератор «Вывода»** (шаблонный текст по правилам, без LLM):
- по баллу: ≥80 «техническая база в порядке, осталось закрыть точечные замечания»; 50–79 / <50 — свои формулировки;
- «Критичных проблем не найдено — блокирующих ошибок нет» или «Критичных: N — начните с них»;
- «Важных замечаний: N, советов: M» + что влияет на что;
- «Самые слабые направления: A (73), B (77), C (85)» — три минимальных категории;
- «Проверено страниц: N. После правок запустите проверку повторно».

**«Пошаговый план»:** 1) Закрыть критичные (если есть) → 2) Закрыть важные (список названий) →
3) Пройти по советам (список) → 4) Проверить сайт повторно и сравнить балл.

## 8. Модуль GEO «Видимость в ответах ИИ» (`/geo`)

Отдельный лид-магнит: называет ли нейросеть компанию, когда покупатель просит совета.

**Форма** (`POST /api/visibility`): `brand` (название как на вывеске, с отличающей частью),
`category` (словами покупателя), `audience` (кто выбирает и платит), `region` (опц.),
`site` (опц.: без сайта меряем карты, справочники, отзовики), `competitors` (до 3, через запятую,
в вопросы **не** подставляются, только ищутся в ответах), `email` (опц., для ссылки письмом).

**Методика (3 правила):**
1. Вопросы генерируются из category + audience + region **без упоминания бренда и конкурентов**.
2. Ответ модели сохраняется **целиком** вместе с источниками/ссылками.
3. **Сбой — это не ноль**: если модель не ответила, это отдельная строка, в знаменатель доли не идёт.

**Объём:** бесплатно — 2 вопроса одной модели (Perplexity sonar). Платно — 6 вопросов × 6 моделей = 36
ответов: Perplexity, ChatGPT, Claude, Google AI Mode (Gemini), Яндекс Нейро (YandexGPT), GigaChat.

**Отчёт GEO:** доля ответов с упоминанием бренда (от пришедших ответов), для каждого ответа —
вопрос, модель, полный текст с подсветкой бренда/конкурентов, упомянут ли бренд, кто на его месте,
источники (домены), статус сбоя. Выгрузка.

У оригинала этот модуль сейчас в **демо-режиме** (ключи моделей не подключены, ответы помечены
как демонстрационные). У нас можно сразу запустить его по-настоящему, это конкурентное преимущество.

## 9. Лендинг: функциональная структура (дизайн будет другой)

Сохраняем **набор блоков и лид-магнитов**, а визуал делаем по новым референсам.

1. **Hero:** бейдж «SEO + GEO аудит · Яндекс · Google · ИИ», H1 про «первым в Яндексе и в ответах ИИ»,
   подзаголовок, **форма URL** (главный лид-магнит), микрокопия «Без регистрации · N проверок · Отчёт за 1–2 минуты»,
   три мини-преимущества (Поиск / Контент / ИИ-ответы).
   У оригинала в hero интерактивный портрет основателя, который следит глазами за курсором
   (спрайт-атлас + JSON с координатами взгляда), и анимированная «бегущая» подсветка поля ввода.
2. **Проблема: «Новая реальность поиска»** — 3 карточки (реклама дорожает / SEO не успевает / ИИ отвечает
   вместо сайта), в каждой CTA «Проверить сайт» → `#audit`.
3. **Как это работает: 3 шага** с мини-мокапами интерфейса: 01 аудит (гейдж 78/100 + категории),
   02 план работ, 03 мониторинг по подписке (график позиций Яндекс/Google).
4. **Что будет в первом отчёте:** цифры из реестра (N проверок, 9 направлений, 4×2 кольца PageSpeed,
   план работ). Честная приписка про отсутствие выдуманных кейсов.
5. **Локальное SEO:** геозапросы, карточки на картах, локальные вопросы к ИИ; мокап карты с пином.
6. **«Сайт переделывать не нужно»:** работает на любом движке (WordPress, Tilda, 1С-Битрикс, Joomla,
   Drupal, OpenCart, самопис).
7. **Честное сравнение:** таблица «Мы / SEO-агентство / Сервисы автопродвижения» по 7 параметрам
   (проверка до оплаты, стоимость, каналы, методы, что остаётся после отключения, отчётность, реакция на алгоритмы).
   На мобиле — карточки вместо таблицы.
8. **Тарифы (4):** Старт 9 990 ₽ · Рост 14 990 ₽ (бейдж «Выбирают чаще») · Лидер 19 990 ₽ · Максимум 30 000 ₽/мес.
   CTA ведут на `/register?plan=…`. Под ними реферальная программа (бонус за приглашённого + скидка ему).
9. **Гарантии (3):** аудит бесплатный без условий / белые методы / условия в оферте.
10. **Журнал (блог):** 4 карточки статей про GEO/AI-SEO + «Все статьи» (контент-маркетинг и SEO лендинга).
11. **FAQ / возражения** (9 вопросов, аккордеон) + «Задать вопрос владельцу» (Telegram).
12. **Финальный CTA** с повторной формой URL.
13. **Виджет-консультант** (без нейросети, по готовым ответам FAQ) с кнопками-вопросами и переходом в Telegram.
14. Футер: юр. документы (оферта, политика, лицензионное соглашение, cookies, оплата и возврат, реквизиты).

**Доп. страницы:** `/geo`, `/agencies` (B2B: отчёт по ссылке для клиента, повторная проверка, единая методика),
`/stati` + статьи, `/pay`, `/offer`, `/privacy`, `/license`, `/cookies`, `/register`, `/cabinet`.

### 9.1. SEO самого лендинга (повторить)
- title ≤ 65 символов, description 70–160, **og:image 1200×630**, twitter `summary_large_image`, `og:locale ru_RU`.
